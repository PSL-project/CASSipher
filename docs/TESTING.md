# Testing protocol

Execute `python -m unittest discover -s tests -v` from the repository root, after `python -m pip install -e .`.

Unit tests exercise:
- All three modern AEAD variants across none/zlib/LZMA/Bzip2 compression.
- Historical Caesar, Atbash, Vigenère, affine and rail-fence reversal on binary data.
- Empty inputs, Unicode filenames, multi-file/folder packaging and source preservation.
- More-than-one-chunk random binary files; output located inside input folder.
- Wrong password, corrupted byte, truncation, trailing data and header tampering.
- OTP pad creation, pad size, decryption, and locally detected reuse.
- Malicious archive path rejection (`..`, Windows drive notation, device names).
- Cancellation before commit; duplicate-output prevention.
- Backward compatibility with a `.cwbox` fixture generated by the original v0.1.0 engine.

**Unverified:** Windows binary execution, live Windows drag and drop, optional zstd pipeline on systems without that module, Python behavior under abnormal power loss, secure key zeroization, formal side-channel resistance, external cryptographic review, malware-resistance, crash remnants. GitHub CI is configured for Windows and Ubuntu unit tests.

Before public v1.0, add: published AEAD/KDF test vectors, adversarial parser fuzzing, security analysis of the custom container, resource exhaustion tests, archival compatibility corpus, integration tests on fresh Windows VMs, independent security audit and direct-streaming implementation eliminating plaintext disk staging.
